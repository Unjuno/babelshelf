# Wllama exact text count extension

This is a source extension for wllama 3.8.1, not a runnable model registration. Existing product manifests still refuse normal LFM harness use. The unchanged distribution has no count API; max_tokens=0 and generation usage are not substitutes.

The patch adds a public countChatTokens method and typed count request/response. Native counting and generation share parse_completion_body, including the upstream OpenAI/Jinja conversion. Counting uses the same text tokenize_input_prompts arguments as server-context.cpp tokenize_cli_input, with special/BOS processing enabled. It rejects media models/content arrays, does not create/post a completion task and does not evaluate/generate tokens or alter a slot. Exact native/browser agreement still needs verification. This source claim is not a measured token count.

Reproduce from wllama commit 7ed17361caf221a84aa1e80ca85a3d6324f3af85 and llama.cpp submodule 46ca246de9bb1c35269722a6240d37d9dfd79cad. On Windows enable core.longpaths only in this isolated checkout before the submodule checkout. Apply count.patch, normalize cpp/glue.hpp to LF before running node cpp/generate_glue_prototype.js (the upstream generator otherwise includes CR in class names). source-pins.json includes the base and patched LF hashes. Run node scripts/check-wllama-count-source.mjs SOURCE_DIRECTORY from the BabelShelf root.

Build tools are isolated under outputs/runtime-development: Emscripten SDK 4.0.20 at e4fe26ef59168ff44f4c23c466e497bf60b3411e, Ninja 1.13.2. No permanent PATH or system SDK activation is required. Current native target is explicitly CPU-only with GGML_WEBGPU=OFF; this is not an automatic runtime fallback. Source the isolated emsdk_env.ps1 in the build process. Configure with emcmake cmake -S . -B build-count-cpu -G Ninja, an absolute CMAKE_MAKE_PROGRAM, GGML_NATIVE=OFF, LLAMA_BUILD_TESTS/EXAMPLES/SERVER=OFF, CMAKE_BUILD_TYPE=Release and CMAKE_OBJECT_PATH_MAX=200. Build only target wllama, parallel4. Default JSPI/memory64 build and Safari compat build are separate acceptance targets; no compat success is claimed here.

Build logs: outputs/runtime-development/count-configure.txt and count-build.txt outside the Git checkout. App runtime/weights/defaults are unchanged. The source extension must be compiled, bundled with matching generated glue/worker code, pinned and verified with actual local models before normal registration. Do not combine this patch's new JavaScript API with an old WASM binary. Preserve wllama's MIT attribution in UPSTREAM-LICENCE, llama.cpp's own license and each model's separate license. None of these clears the independent WebML runtime redistribution question.
