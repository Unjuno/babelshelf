## Two different file actions in Models

The Models screen separates **Add or choose model** from **Files for selected model** for Text and Decision. The first group selects a registered/built-in choice or inspects a new compatible custom package and, after review, registers a new identity. **Import or repair [selected model] files** restores or completes that model's exact verified package; it does not register or select another model. A GGUF carries its tokenizer metadata and chat template inside the file; a matching app-owned runtime is still required. ONNX packages need their separate weights, config and tokenizer files. The Decision custom route accepts only the D1 text adapter, not arbitrary ONNX or multimodal D1 graphs.

The earlier [Prism Ternary Bonsai 8B GGUF](https://huggingface.co/prism-ml/Ternary-Bonsai-8B-gguf) is Qwen3-based. Its repository now offers three distinct ternary packings at the pinned revision: the deprecated 2,182,184,672-byte `Q2_0.gguf` (legacy group-128 under type 42), the current 2,310,125,920-byte `Q2_0_g64.gguf` (official group-64 under type 42), and the 2,182,184,672-byte `PQ2_0.gguf` (Prism group-128 under type 142). [Prism's format matrix](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/MODEL-FORMATS.md) says the current group-64 file runs on recent upstream llama.cpp; PQ2_0 still requires Prism kernels. The older filename must not be mistaken for the current upstream-compatible packing. These native llama.cpp claims do not establish support in this PWA's packaged browser engines. Before the current Qwen3 CPU addition, imports supported Qwen3.5/PTQ1_0 and LFM2 GGUF through fixed adapters; neither its WebML Qwen3.5 path nor its pinned wllama LFM2 path is a verified Qwen3/ternary 8B engine. Local Qwen3/ternary intake stops after bounded header inspection, before whole-file hashing or registration, with a specific unsupported-engine error. Public Hugging Face repositories declaring Qwen3 in root config are refused during discovery; GGUF-only repositories are inspected at file selection and refused before whole-file acquisition. This is a compatibility refusal, not evidence that 8B cannot ever run in a browser or fit a phone. The distinct Bonsai 2 9B Qwen3.5/PTQ1_0 remains an optional pinned candidate with unstable PC prose and unverified phone behavior.

**Add text model** opens the role library. Adding a new supported model registers a new identity. A local compatible Qwen3.5 or LFM2 GGUF contains tokenizer metadata and a chat template; the app inspects the file before the user confirms Add. This does not make arbitrary GGUF architectures compatible. **Import files for [selected model]** supplies or repairs the exact files for the *already selected* model and does not create a new entry or change its identity. Built-in ONNX text models instead require their matching weights, configuration, and tokenizer package files. These actions remain separate so that importing bytes cannot silently switch the active model.

Decision's **Add decision model** opens its library, where a compatible five-file D1 text-adapter package can be added, including tokenizer files. The separate import for the selected built-in D1 supplies its pinned files without registering a new model. Adding a model and proving it loads or produces useful decisions are separate checks. Speech has the analogous fixed Whisper package flow. OCR and image understanding currently have no custom-model adapter; selecting a generic ONNX file cannot turn them into one. Settings > Media reading separates adding an original PDF/image/audio/video from configuring its OCR/Vision/Speech reader. Each reader status opens the corresponding role in Models. Video frames remain unsupported; audio transcription never counts as frame understanding.

## Current implementation

- **Text:** local GGUF import through app-owned Qwen3.5/WebML or LFM2/wllama adapters. These accept only their inspected formats and do not imply arbitrary GGUF/fine-tune compatibility. LFM2.5-230M has a recorded PC offline generation/save flow at Unit258.
- **Decision:** custom local ONNX registration now accepts only the fixed D1 text-adapter package: `config.json`, `tokenizer.json`, `tokenizer_config.json`, `onnx/model_quantized.onnx`, and `onnx/model_quantized.onnx_data`. The config must declare `d1_omni` with 16,384 context; imports are capped at 2 GiB and stored by verified SHA-256 in OPFS. The app-owned Decision worker retains its pinned ONNX Runtime, tokenizer/marker contract, input cap and fixed graph I/O checks. Custom weights must load successfully through that adapter before they can be considered runnable. Arbitrary ONNX, D1-3B multimodal graphs, user-supplied code, and new Decision architectures remain unsupported.
- **Speech:** custom import supports only a bounded eight-file Whisper ONNX package (`config.json`, generation/preprocessor/tokenizer metadata, quantized encoder, and merged quantized decoder) through the app-owned Transformers.js 3.8.1 + ONNX Runtime Web WASM adapter. Import hashes and keeps the files in OPFS; custom verification is always local. PC Chrome has run one real offline transcription before and after page reload (Unit263 follow-up), so the UI's execution-untested status describes initial registration only. One short synthetic sample produced text but did not establish recognition quality. The adapter caps input audio at two minutes. Other speech architectures and arbitrary ONNX graphs remain unsupported.
- **OCR/Image:** only the app-owned Tesseract path is connected; custom OCR and image-description model imports are not implemented.
- **Media understanding:** custom image-description and video-frame models are not connected. Audio extraction uses the speech role and does not make a model multimodal.

The Text, Decision, and Speech selectors include user-added declarations in their corresponding libraries. A compatible package may be registered and locally verified without claiming successful model loading or useful output. Import review labels execution as untested; Decision and Speech load through fixed app-owned adapters. Model bytes and revisions are content-pinned. Model weights stay in origin-local OPFS and are excluded from knowledge backups. Speech transcripts record the exact custom model ID and content revision that produced them.

The model settings present standard and custom entries through the same role selector. An Add model sheet offers file import only for roles with an app-owned compatible adapter. Unsupported model candidates remain disabled with the actual runtime limitation. Users may replace their selection explicitly; importing never silently changes another role. The default text model remains Bonsai2 4B.

### Public Hugging Face source

Settings > Models > Text > Add model > Find on Hugging Face accepts a public `owner/model` repository ID. The feature is unavailable while Downloads & updates is OFF. When ON, repository metadata and `config.json` are read without credentials or a referrer; the repository `sha` is pinned and shown as a commit prefix. Only `qwen3_5` (Qwen3.5 adapter) and `lfm2` (LFM2 adapter) configurations are offered. Only single-file `.gguf` candidates up to 8 GiB are listed; split GGUF parts are not offered. The chosen file is downloaded by its pinned commit into a private OPFS staging directory, then passed through the ordinary local GGUF inspection and adapter compatibility checks. A mismatch, cancellation or failure removes the staged file. Add still opens the existing local model review; only explicit Add copies it into model storage and selects it.

The custom model record retains the public repository ID, full commit SHA, selected relative file path and reported license label alongside the content SHA-256. A missing/unknown license is kept as unknown; no model card license is inferred, and model licensing does not establish runtime redistribution rights. No prompts, notes, attachments or other user data are sent. Inference remains local. This path does not guarantee a model will load or generate successfully on a given device, and listing a repository does not certify its license or quality. The local custom-file flow remains available independently of Hugging Face.

## Trust and lifecycle

The lifecycle is: choose local files → inspect bounded metadata → show accepted role/format and app-owned engine → explicitly import and hash → register in canonical settings → locally verify → load through that engine → report actual execution identity. Each stage has a distinct state. Readiness cannot be written into a settings file or restored from a backup. App-owned runtime, model and runtime-license pins remain separate; model licenses do not grant redistribution rights for the engine.

A role registry describes trusted app-owned adapters and their actual formats/capabilities. A model record binds bytes to an engine ID/revision, role, inspected metadata and SHA-256 pins. Tokenizers, chat templates, preprocessing, context and resource bounds are part of the compatibility contract. ONNX and GGUF are containers, not universal runtime promises. Model input/output cannot grant network access, arbitrary MCP/tools, knowledge writes or runtime code execution.

Imported weights are explicit local files. Preparation and verification never fetch custom model bytes. Built-in network acquisition is separate, user-controlled and off by default. Backups preserve validated model declarations and selected role, but exclude model/runtime assets; restore never manufactures local readiness.

Initial preparation budgets only assets that its built-in adapters can acquire. A selected custom Whisper or D1 package contributes zero download bytes and is reverified locally even with Downloads & updates OFF. Missing custom files require explicit reimport; toggling network access cannot supply them. The displayed operation and the actual worker call use the same allowNetwork value. This estimate is a transfer budget, not a RAM or storage guarantee.

## Extension and acceptance rules

Add a role/engine only when BabelShelf has app-owned adapter code and pinned runtime/license/assets for it. Tests should cover registry role isolation, hash verification, offline behavior, cancellation, selection and honest error states. A real model load is required before calling the model runnable; real task quality and device acceptance are separate evidence. Do not broaden support by filename, catalog label, successful parsing, synthetic tensors or a model's own capability claims.

No general-purpose custom runtime/plugin loader is planned. Custom checkpoints are usable only when structurally and numerically compatible with an existing trusted adapter. New architectures require an explicit engine implementation and separate review. Preserve prior preference bytes and histories when schema fields are added.

## Worker registration and local preparation (Unit61)

The shared worker now supports configure({models}) only after init and while unloaded. Each declaration is revalidated and extends a copied built-in manifest; runtime pins, context budget and built-ins cannot come from a custom record. Invalid configuration retains the prior registry. Custom records construct hash-derived GGUF filenames with no download URL and no inferred model license.

Custom prepare requires modelFile and allowNetwork:false. Optional localFiles can contain the fixed runtime.js; otherwise a real cached runtime must independently match its pinned size/hash. Metadata and full model bytes are independently verified before storage. Content-addressed weights can share bytes with an already prepared built-in while retaining separate registration/readiness identity. Load repeats metadata/weight verification and pinned runtime verification, then uses only the existing app-owned Qwen3.5 constructor and local-only fileResponse fetch. No registry field enables network, knowledge writes, arbitrary model code, a larger context window or device compatibility.

All worker cached asset hashing uses the streaming cancellable helper. Fresh copying cancels pending reads on AbortSignal, checks after reads/before close, yields between bounded copy work, aborts incomplete writers and releases readers. Cancellation during valid cached verification never opens a replacement writer or deletes the retained asset. Preparation receipts remain file checks, not generation/offline certifications.

This worker API is not yet connected to the product Add-model UI/hook. scripts/qa/custom-model-worker.mjs explicitly drives the real worker in an isolated native Chrome profile and labels that scope. Importing the official4B file as a custom identity proves that execution path, not an independently trained model's compatibility. Runtime-specific license remains unresolved and runtime is not redistributed.

## Bounded remote GGUF admission (2026-10-21)
Hugging Face discovery also admits public GGUF-only repositories without a root config.json. These are labelled compatibility not checked; a filename is not a compatibility declaration. When root config exists, its existing architecture checks remain. Before any whole-file request or OPFS staging file, selection performs a Range request for at most the same 16 MiB budget as inspectGGUF and applies the shared app-owned eligibleTextEngine rules. Known repository architecture must agree with the actual GGUF. A large response ignoring Range is cancelled without reading its body. Changed exposed range/size, excessive/truncated streams and Stop refuse admission. Header checks do not hash payloads, prove integrity or certify inference: complete downloaded-file inspection, SHA-256, explicit Add, local verification and device testing remain required. No arbitrary runtime code or new inference engine is admitted.
