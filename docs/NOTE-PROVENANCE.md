# Saved note provenance

Memory must distinguish a saved assistant message from the knowledge originals behind it. An actual sidebar inspection of QA-星見要約.md v1 exposed only the body and Original message; its stored source to QA-星見.md v2 was invisible although that original had reached v6. projectNote declared optional kind/sources but dropped both from the UI projection.

The projection now carries canonical kind and detached, whitelisted source IDs/revisions/ranges/quotes. A validated citedQuote substring is retained for the existing precise media/page/time adapters. It does not migrate records, change source admission, or discard unknown canonical fields during an edit. The optional Sources disclosure appears only for sourced/generated notes. Plain original notes gain no extra control.

note-provenance.ts reads the full canonical snapshot and separates historical availability from current grounding admission. Current means validateGroundingRefs accepts the pinned revision and its complete ancestry, not that an answer is factually correct. Changed means that source chain is no longer current. Removed means the original is withdrawn but its historical bytes remain. Unavailable covers missing/invalid historical references; these cannot open a fabricated preview. A saved generated note with no sources is explicitly unavailable.

Source rows name the pinned historical path/version and, for a direct version change, the current version. The existing citation viewer opens the exact original revision/range and its existing media preview adapters; Open file remains the distinct current-file action. Withdrawn originals can still be inspected historically, while the current-file action is disabled when absent from active Memory. The note body, history, references, eligibility rules and stored assistant original are never rewritten or regenerated by this feature.

The disclosure refreshes from local canonical storage on selection, local snapshot changes, focus and expansion. It reuses PreviewSelection so late or superseded reads cannot replace the current display. Failed checks show a short error/Retry, not a current-source claim. No model or external resource is acquired. The status is a checked snapshot, not a guarantee against a subsequent concurrent edit.

Verification distinguishes pure canonical projection/graph tests, controlled browser fixtures and the actual preexisting sidebar QA records. Tests cover direct and ancestral changes, removed/missing/invalid sources, historical versus current body navigation, 44px targets, enlarged text and preserved records. Browser fixtures do not prove model generation or physical iPhone behavior. See TEST-RESULTS and USABILITY-EVALUATION for exact build scopes.

The current-file action reads availability from the fresh canonical source record, then refreshes the active Memory snapshot on activation. A concurrently withdrawn source cannot open through stale React notes; a concurrently revised source opens its latest body. Controlled browser tests change canonical records after the UI is loaded and after the historical viewer opens, and verify unchanged records. The historical viewer remains pinned to its original version.

The shared Source viewer also shows the current direct-file version when it differs from the cited revision, or File removed for a withdrawn source. This is the canonical snapshot read when opening the viewer; it does not prove currentness after later edits or validate an ancestral source chain. The exact historical body remains unchanged.
