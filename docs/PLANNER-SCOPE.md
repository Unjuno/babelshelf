# Request-scoped planner generation — Unit72

Unit71 actual offline Send generated `target=inputs` without attachments and a historical index3 outside the available two prior turns. The parser rejected these correctly. Root cause at the generation boundary: the global grammar advertised every target and any integer regardless of the harness-owned request snapshot. This is distinct from semantic misrouting of Hello and invalid grounded-answer JSON; those failures are not fixed by this change.

Derive a small immutable scope from the exact planning context: submitted inputs, opened file, current result, prior turn count. Share scope filtering between the advertised action catalog and optional structured decoding. Exclude unavailable targets before token selection and bound historical indices to the actual prior-turn range. Keep ordinary conversation, new reviewed capture/schedule, knowledge search and exact paths available. Do not manufacture a route, reinterpret an invalid response, suppress a failure or grant writes. Speaker availability, semantic correctness and canonical/source validation still require their existing downstream checks.

Dependencies: harness-actions → structured grammar/token filter → existing TextEngine format transport; conversation constructs scope before generate. Other engines may ignore optional generation constraints; strict output validators remain mandatory. No model-specific prompt variants or model/default changes.

The first actual scoped trial exposed a second structural gap: a valid turn index may have no assistant answer because its attempt failed. Canonical dialogue now supplies the exact sorted assistant-answer index inventory, including archived originals; failed status messages and lossy summaries never create assistant originals. User-index grammar size scales with decimal width rather than turn count; assistant selectors permit only actual retained answer indices. No history is deleted. Legacy manually constructed contexts derive available assistant indices from their supplied recent originals.

Acceptance: negative controls for zero history/no inputs/no focus, positive controls for explicit paths/capture/current inputs and exact history bounds including digit boundaries; transport scope is preserved; full tests/build/protected-runtime check; one actual PC offline normal Send comparison with failed originals retained. A structural improvement does not establish general dialogue quality or physical-device acceptance.
