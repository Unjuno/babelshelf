## Boundaries

A second actual run on b6532b949a122a3e showed that scope isolation alone still let the model choose chat and interpret a text correction as a physical water-to-tea request. Therefore bounded explicit named corrections now select an application-owned discovery route before action planning. This admission only extracts a search subject; it never invents replacement bytes. One current candidate proceeds to review generation; multiple candidates open a shared glass Choose file sheet before any model acquisition. Cancel retains the request and records Edit cancelled. Selection is checked against the offered IDs/versions and a fresh canonical, editable path read. The independent agent-loop correction path remains available for unmatched wording.

- A request explicitly naming saved/stored knowledge, without competing deictic-file or earlier-dialogue references or current attachments, gets a transient empty dialogue planning context. Both model format scope and post-generation validation exclude unavailable current/history/file selectors. Original dialogue, pins, compaction and knowledge remain unchanged.
- The same scope is used by context preparation and turn routing. No unrelated compaction, regeneration of past summaries, or implicit current-file binding occurs. Mixed current-input/current-file/history references retain their existing routes; this is not a general language or ambiguity solver.
- The existing bounded, registered read-only agent tools still perform discovery. No model-specific replacement vocabulary, fabricated result or new write tool is added. memory.search file metadata survives projection as navigation metadata, never citation content.
- After tools, an edit/path final is admitted only when one exact ID/path/filename resolves to one ID/version in successful built-in memory.search or memory.read results. Custom tool output, invalid attempts, invented paths, conflicting versions and ambiguous names cannot nominate a correction.
- Before generating a proposal, a fresh canonical read must agree with that exact ID/version and resolve the requested path/ID/name to the same file. Withdrawal, revision change, rename or mismatched identity fails. The existing editable-file validation still applies.
- The complete original and instruction then enter the existing proposal generator. Preparing the proposal writes no knowledge. Durable review, full Before/After, explicit approval, whole-record CAS, history and Undo remain the only commit path. Existing pending reviews retain exclusivity.
