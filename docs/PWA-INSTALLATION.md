## Local startup

Run `npm run build:app`, then `npm run dev:app -- 4180` when that port is free. The server defaults to4182 without the argument. Keep the same origin/port to access existing browser storage; another port is a different origin, not a migration. Do not clear existing data to update the app. Existing tabs may require the explicit Settings/Connection app-update flow and should return Downloads to OFF afterward.

## Native PC check

`node scripts/qa/installed-pwa.mjs NEW_ABSOLUTE_PROFILE NEW_ABSOLUTE_OUTPUT` serves the built app on its own temporary loopback origin, registers it through native Chrome CDP PWA.install, sets the test installation's native display preference to standalone, then launches it through PWA.launch. This preference is needed by this CDP setup: installation alone originally opened browser display and the strict assertion failed. The test never changes matchMedia or emulates a successful standalone result. Both paths must be new: the runner refuses an existing profile and removes the profile after verification by default. Add `--retain-profile` only when a follow-up inspection needs that fresh test profile; evidence/output is retained separately. Ctrl+C and graceful termination close the active Playwright context before the run's owned temporary profile is removed. A hard process kill or power loss can still leave an orphan, which is never auto-discovered or purged by a later run. The runner removes the desktop app shortcut associated with its profile on exit.

For a one-off check, omit both arguments: the runner creates unique temporary paths and removes both the fresh profile and generated results directory on exit. To keep evidence for review, pass a new explicit output path; to keep the fresh profile for debugging, pass a new explicit profile path and `--retain-profile`. A caller-supplied profile is otherwise removed after the run. The QA runner never reuses or purges an existing profile or explicit output path.

The same existing record/import/search/edit/history/index/backup/conflict/no-op-restore flow runs in three distinct persistent browser processes. After first preparation the fixture server stops; later browser processes are offline before PWA.launch. Every phase must report actual standalone=true, browser=false, expected build and a different browser PID. The registration and fixture state live in the isolated profile only for the duration of the run unless `--retain-profile` was explicitly requested. Evidence archives remain only when the caller supplied a fresh output directory. Existing personal/maintained profiles and output folders are not migrated or cleared.

`node scripts/qa/verify-installed-pwa.mjs OUTPUT` independently production-parses all four backup archives, cold-launches that installed test app offline, checks its expected Service Worker build and decodes all three PNGs to verify dimensions and every opaque-white pixel.
