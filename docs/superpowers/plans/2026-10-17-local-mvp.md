# Local MVP Implementation Plan

> For agentic workers: use superpowers:executing-plans to implement this plan task-by-task. The user authorizes implementation and verification without another design approval round.

**Goal:** Connect the accepted UI to real local records and verified local inference, retaining the complete goal and evidence gates.
**Architecture:** Keep `mlb-memory-v1` notes/revisions as canonical; project them into UI fields through an adapter, not a second knowledge database. Commit UI mutations in a single IDB transaction with expected records, append-only history, baseline source preservation, protected roots and validated settings. Separate derived search, original blobs and asset readiness from editable metadata. Build an installable production entry separately from the protected phone preview runtime.
**Tech Stack:** React/TypeScript UI; existing JS core/storage/search; IndexedDB/OPFS; pinned Bonsai worker; bundled PWA shell.
**Spec:** user goal, PRODUCT-SPEC.md, STORAGE-CONTRACT.md, MEDIA-HARNESS.md. Latest user choices override chronological notes.

## Constraints / review focus
No remote inference, silent downloads, database resets, user-data upload, fake generation or deployment. Preserve IDs, revisions, exact sources, withdrawal and legacy paths. Protected mobile runtime stays intact. Check stale-tab races, old settings records, empty folders, Unicode paths/quotes, storage failures and interrupted writes.

## Work units and evidence
- [ ] Canonical adapter: read legacy notes, initialize only missing defaults, transact edits/withdraw/restore with version/path validation. Tests for round trips, unchanged source fields/history, collision/stale rejection; real browser capture/reload/search/edit/history.
- [ ] Durable UI: remove fixture conversation, hook record mutations to adapter; store folders/recovery/input originals separately without claiming OS files. Connect literal capture/search/read; import actual TXT/MD. Browser reload and two-tab conflict checks.
- [ ] Tool harness: bounded proposals with expected revision, review, receipts and revision-based undo; generated-answer save uses exact result and sources. Reject authority from retrieved text.
- [ ] Canonical tasks/events/runs: typed Markdown records, dedicated views read them, recurrence/missed/idempotency state, local foreground execution only with honest suspended-PWA limits.
- [ ] Asset/engine integration: reuse pinned worker, inspect upstream compatibility/license, connect explicit prepare/load/unload/stop. Record actual GPU availability; test 4B then 2B as necessary. Keep other roles unprepared until adapters exist.
- [ ] Original assets/extraction: persist hashes/blobs and source ranges; real local ASR path if compatible; media remains unprepared when unsupported.
- [ ] Production PWA entry/build: approved UI without simulated phone keyboard; versioned verified shell, no network fallback. Separate runtime entry rather than altering protected preview runtime.
- [ ] Backup/restore and offline acceptance: full state and exact references, conflict report; prepare assets then disconnect/reopen and exercise all flows. Physical Android/iPhone gates remain explicit until tested.
