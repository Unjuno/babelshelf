# Continuous input context

The Input surface has one continuous local dialogue, with no session picker or New chat concept. Canonical knowledge stays in the notes store; conversation is working context and does not automatically create knowledge notes. Saving a proposed capture or an existing answer still requires the existing review/Save operation.

## Persistence

IndexedDB `mlb-memory-v1`, existing schema1 `settings` store, key `ui-v1-dialogue`. This auxiliary record holds schema/revision, original user/assistant turns, statuses, attachment descriptors, exact source references and a compaction cursor/summary. It does not store object URLs or claim durable media storage. Metadata after a restart marks media previews unavailable. Original TXT/MD records remain separately canonical.

Writes compare the entire expected previous record inside one read/write transaction. Concurrent tabs cannot silently overwrite each other's conversation; a conflicting tab must reopen. A submitted turn is persisted before inference. An unfinished turn is marked interrupted after reopening; it is not automatically replayed. All original turns remain available in the local record and visible Input history after compaction. This auxiliary record is currently excluded from the note-only brainpack; full auxiliary-state export/recovery remains a whole-MVP gate.

## Model context

The actual pinned Bonsai tokenizer counts messages; no character/token equivalence is assumed in production. At the current prepared 2048-token context, history is budgeted to at most850 tokens (42% for smaller contexts), reserving room for policy, the latest request, evidence and the256-token answer. When needed the same local model summarizes an oldest prefix, carrying the previous summary forward. The latest exchange stays verbatim where capacity allows. Summary calls have their own exact count checks and192-token output budget. Oversized current messages return a context error and retain their original bytes. Oversized historical turns are summarized in Unicode-safe pieces bounded by actual token counts, so a rejected input cannot permanently block later short requests. Failures/stops never substitute an invented summary.

Routing can request a read-only, zero-based historyIndex and user/assistant speaker. The harness checks bounds and reads exact bytes from the immutable prior dialogue, scopes the answer to that original, and retains a readTurn receipt. This handles explicit first/previous-message references without trusting fuzzy recall or the summary. A capture of an earlier assistant answer reuses its exact bytes/references in the standard new-note review. No regeneration occurs during capture/save.

The summary, recent turns, and up to four exact archived user excerpts (including a following statement for correction context) reach both routing and answering. Archived excerpts use the existing multilingual local search over a derived in-memory conversation index; this creates no knowledge notes. Excerpts include turn index/ID/range and focus around matching text with normalized-to-original UTF-16 mapping. They are shrunk/omitted using actual tokenizer counts within a240-token recall budget inside the history budget. Chronological context and later corrections take precedence; an old excerpt never automatically overrides a newer correction in the summary. Dialogue-only routing does not inject unrelated note-search evidence; note answer/summary routes retain validated grounding. Canonical source IDs/revisions/ranges/quotes are retained separately, validated against current notes, and budgeted as evidence. Old withdrawn/changed evidence is excluded; a source changing during generation rejects the answer. Dialogue replies use an answer-only JSON schema; they are not files and never receive fabricated file citations. Nonempty invented citations still fail validation. Note answer/summary uses the cited schema. Citation-free dialogue responses have no fabricated references. Stop is checked across budgeting, generation and completion, including the gaps between worker operations. Such saved generated prose retains `kind=generated` and empty sources; the baseline eligibility policy excludes unsourced generated prose from evidence search.

Conversation/summary, attachment text, tool results and scheduled prompts are untrusted data. They cannot authorize a write, delete, network request or tool installation. Contextual capture resolves content into a new-note proposal; the model cannot save it itself. Scheduled generation has no access to the interactive conversation and remains evidence-only/read-only.

## Verification boundary

Node budget/routing/source checks use deterministic test doubles solely to test control flow, never as evidence of actual generation. Real browser storage checks use a unique retained test database. Actual Bonsai conversational generation and compaction are recorded separately in TEST-RESULTS and MODEL-RUNTIME-VERIFICATION. Summary quality is lossy; it is not a guarantee that every old detail will remain in active context. Original history and knowledge sources are retained for verification.

## Observed semantic failures and recovery

Real4B tests exposed a lossy summary attributing a retrieved note code to the user and lexical snippets selecting similar questions while omitting the actual value. The explicit original-turn read path was added after inspecting actual engine inputs/outputs. The model then produced the correct original value; an invented S1 reference was correctly rejected, leading to a separate answer-only dialogue schema. Original failed turns remain retained. This is not a guarantee of flawless summarization or reference resolution; original reads, citation validation and explicit save review remain necessary. Temporary diagnostic prompt logging was removed.

The final build visibly answered the correct original value after server-unavailable fresh-tab startup. A subsequent request to split that value into two lines repeated the unchanged value; that formatting test failed. These are model-quality boundaries, not evidence that every contextual instruction succeeds. See MODEL-RUNTIME-VERIFICATION.md for the build and environment.
