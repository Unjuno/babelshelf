## Harness-owned current result — Unit32

This section supersedes the Unit31 competing-speaker dispatch below. Models are replaceable adapters; current work identity must not depend on a second model selecting A/B after another selected the wrong old instruction.

Dialogue schema1 has optional `currentResult: {turnId}`. Completing a nonempty assistant answer persists this pointer in the same expected-dialogue CAS write. Audit/status-only updates, failed submissions, saving a note and compaction preserve it. The pointer resolves exact retained assistant bytes and references; it does not copy an answer or make generated prose canonical knowledge. Historical records without a pointer derive the latest nonempty answer without rewriting any stored turns. Validation and state-backup validation reject a dangling pointer.

The planner contract separates `target: current` from `target: history`. Current accepts no competing history index/speaker and resolves the stable harness-owned ID from the immutable prior snapshot. History requires explicit bounded index and speaker. Recall/transform without either typed target fail; raw invalid output stays on-demand evidence rather than being repaired into a guessed operation. Indexed capture remains compatible; current-result capture reuses exact original bytes/references in the existing review, without regeneration. This is an adapter protocol change, not a new permission.

Normal Send no longer calls dialogue.subject or performs a competing-speaker generation. Its module and historical receipt validator remain for retained diagnostic evidence and existing backups. text.inspect still selects finite read/split/replace arguments; the harness performs literal operations and checks targets, sources, bounds, Stop and persistence. The model can still choose an incorrect action or explicitly historical target: this architecture does not claim universal intent understanding. Current work currently covers completed dialogue results; canonical-file/task working targets and further adapter extraction remain follow-up work.

# Continuous input context

The Input surface has one continuous local dialogue, with no session picker or New chat concept. Canonical knowledge stays in the notes store; conversation is working context and does not automatically create knowledge notes. Saving a proposed capture or an existing answer still requires the existing review/Save operation.

## Persistence

IndexedDB `mlb-memory-v1`, existing schema1 `settings` store, key `ui-v1-dialogue`. This auxiliary record holds schema/revision, original user/assistant turns, statuses, attachment descriptors, exact source references and a compaction cursor/summary. It does not store object URLs or claim durable media storage. Metadata after a restart marks media previews unavailable. Original TXT/MD records remain separately canonical.

Writes compare the entire expected previous record inside one read/write transaction. Concurrent tabs cannot silently overwrite each other's conversation; a conflicting tab must reopen. A submitted turn is persisted before inference. An unfinished turn is marked interrupted after reopening; it is not automatically replayed. All original turns remain available in the local record and visible Input history after compaction. The accepted product's schema2 state brainpack now includes this auxiliary record and validates its historical references. Schema1 baseline exports remain note-only. See BACKUP-CONTRACT.md for conflict behavior and media/device recovery limits.

## Model context

The actual pinned Bonsai tokenizer counts messages; no character/token equivalence is assumed in production. At the current prepared 2048-token context, history is budgeted to at most850 tokens (42% for smaller contexts), reserving room for policy, the latest request, evidence and the256-token answer. When needed the same local model summarizes an oldest prefix, carrying the previous summary forward. The latest exchange stays verbatim where capacity allows. Summary calls have their own exact count checks and192-token output budget. Oversized current messages return a context error and retain their original bytes. Oversized historical turns are summarized in Unicode-safe pieces bounded by actual token counts, so a rejected input cannot permanently block later short requests. Failures/stops never substitute an invented summary.

Routing can request a read-only, zero-based historyIndex and user/assistant speaker. Only explicit recall, capture and transform actions with a valid explicit speaker dispatch that read; an incidental index on ordinary chat is never an instruction to read an original. The harness checks bounds and reads exact bytes from the immutable prior dialogue, scopes the answer to that original, and retains a readTurn receipt. The full retained history supplies lastAnswerIndex separately from turnCount so a save-only/failed turn is not advertised as the last answer. This handles explicit first/previous-message references without trusting fuzzy recall or the summary. A capture of an earlier assistant answer reuses its exact bytes/references in the standard new-note review. No regeneration occurs during capture/save.

Explicit literal transformations use a separate operation-selection prompt. The executable operations are text.replace (literal find/with) and text.split_lines (literal delimiter, replaced by newline) over the exact selected dialogue text, using split/join with no regex or code execution. Splitting never asks the model to compose the transformed output. They return a new answer and a structured toolCalls receipt with target ID/index/speaker, typed arguments, match count and result/error. An on-demand Details mark opens the retained original, operation arguments and result/error; normal Input does not list internal diagnostics. Multiline results preserve their line breaks. It cannot edit a knowledge note. Invalid/empty/ill-formed parameters, missing matches, unchanged/empty results, more than1000 matches or output over30000 UTF-16 units fail visibly; they are not accepted as successful rewritten answers. Stop and actual context counts are checked before accepting a result. Generic semantic rewriting remains model generation; this tool is not an arbitrary edit capability.

The summary, recent turns, and up to four exact archived user excerpts (including a following statement for correction context) reach both routing and answering. Archived excerpts use the existing multilingual local search over a derived in-memory conversation index; this creates no knowledge notes. Excerpts include turn index/ID/range and focus around matching text with normalized-to-original UTF-16 mapping. They are shrunk/omitted using actual tokenizer counts within a240-token recall budget inside the history budget. Chronological context and later corrections take precedence; an old excerpt never automatically overrides a newer correction in the summary. Dialogue-only routing does not inject unrelated note-search evidence; note answer/summary routes retain validated grounding. Canonical source IDs/revisions/ranges/quotes are retained separately, validated against current notes, and budgeted as evidence. Original read receipts may carry source references for persistence, but model serialization explicitly projects only turn ID/index/speaker/quote/range; references never leak through dialogue excerpts. Reading user text does not inherit the paired assistant answer's references. Old withdrawn/changed evidence is excluded; a source changing during generation rejects the answer. Dialogue replies use an answer-only JSON schema; they are not files and never receive fabricated file citations. Nonempty invented citations still fail validation. Note answer/summary uses the cited schema. Citation-free dialogue responses have no fabricated references. Stop is checked across budgeting, generation and completion, including the gaps between worker operations. Such saved generated prose retains `kind=generated` and empty sources; the baseline eligibility policy excludes unsourced generated prose from evidence search.

Conversation/summary, attachment text, tool results and scheduled prompts are untrusted data. They cannot authorize a write, delete, network request or tool installation. Contextual capture resolves content into a new-note proposal; the model cannot save it itself. Scheduled generation has no access to the interactive conversation and remains evidence-only/read-only.

## Verification boundary

Competing-speaker binding (`dialogue-subject.ts`) now follows an indexed recall/transform proposal when it identifies a USER original and a latest ASSISTANT answer exists. Both exact originals are read from the same immutable prior snapshot and audited. A separate bounded64-output-token model step receives only index/speaker/exact text and the final literal current request; it may select supplied A/B or refuse with none. No summary, source-reference payload, write permission or generated replacement enters this decision. Count/Stop/strict finite validation fail without guessing. Final readTurn, refs, text.inspect and literal receipt all use the exact chosen original object; the original planner proposal remains recorded separately. Invalid raw output is bounded on-demand failure evidence, never new history or a retry instruction.

This primitive never reselects an ASSISTANT original against another ASSISTANT: a real broader comparison failed that chronology control. No-latest cases keep existing original behavior, and capture bypasses the additional step and still reuses exact existing bytes. Unit31's actual ordinary first-user-code -> latest-code split flow succeeds and saves/reloads the exact two-line result; source selection generally remains model-dependent. Keep the failed broad control and earlier native failures. See research/evaluations/subject-original.md for scope and latency.

Planner input now ends with the exact current request in its own user message. Prior summary/recent turns/archived excerpts and current attachment descriptors are a preceding explicitly untrusted context block; they never become the latest instruction. The policy,160-token allocation, exact counting and finite validation stay unchanged. This improves the observed similar-archived-request target error but is not a guarantee of correct source selection.

An indexed `recall` or `transform` first resolves the exact original, then uses a common `text.inspect` stage. The bounded local model selects **read**, **split_lines** or **replace** from the current instruction and that original alone. `read` has no model-supplied answer or extra fields and proceeds to the existing source-scoped answer generation. A literal operation is applied by the existing bounded deterministic processor and retains its exact original/arguments/match count/result receipt. Failed literal operations never fall back to generated transformed prose. The top-level planner's recall-versus-transform choice therefore does not bypass a requested literal operation; both use this same original-processing stage. Capture still reuses the selected original without this extra generation or regeneration on Save. No activity/receipt becomes model history or write authority. See Unit28 measured outcomes and failed alternatives.

Compaction carries the preceding working summary as a literal, explicitly untrusted user-message block. Archived turns are projected to dialogue fields and serialized to JSON once; oversized JSON fragments are passed literally with first/continued labels. A summary or an already serialized fragment must not be embedded in another JSON string on each cycle. Exact tokenizer counts still bound every call and the output allocation remains192 tokens. This prevents application-added recursive escaping; it does not guarantee that the model preserves every detail or literal character. Existing summaries are never silently unescaped or repaired, and original turns stay unchanged. See Unit27 evidence in TEST-RESULTS.txt.

Node budget/routing/source checks use deterministic test doubles solely to test control flow, never as evidence of actual generation. Real browser storage checks use a unique retained test database. Actual Bonsai conversational generation and compaction are recorded separately in TEST-RESULTS and MODEL-RUNTIME-VERIFICATION. Summary quality is lossy; it is not a guarantee that every old detail will remain in active context. Original history and knowledge sources are retained for verification.

## Working speech input

Reviewed ASR Use text preserves existing composer text, appends the recognized words and stages the verified original plus recognition metadata. Send compares the exact expected dialogue and atomically writes fresh raw originals, their empty initial projections and the turn. Existing active originals may be referenced again without copying bytes or creating another projection. ASR text used as a question is working context, not an automatically indexed knowledge transcript. Save note remains explicit and separate.

Each voice descriptor retains the original/model/language/estimated segment chain and an optional exact occurrence range in turn.user. User edits or duplicate recognized words remove that occurrence claim while retaining the actual recognition. Import and submission validate voice metadata against raw hashes and ranges; an arbitrary Transcript reviewed status cannot enable reading. New references to withdrawn originals refuse; historical turns retain their source. Runtime history projects only descriptor name/kind/status, while retained user text remains available for real compaction/original-turn recall.

## Current retrieval and model output boundary

Current-query excerpts receive token-budget priority. When the top current result is absent from prior validated references, factual generation starts with the current evidence and resolved retrieval query; unrelated prior conversational prose/pins are omitted. The preceding planner still receives bounded conversation to resolve follow-ups. Same-source and genuinely empty-query follow-ups retain their context. Any result invalidated between search and snapshot validation rejects with Source changed before historical fallback, and cited sources are validated again after generation.

Stored-knowledge answers with selected evidence require a verified exact-substring citation. This checks identity/version/bytes, not semantic entailment or model accuracy. Ordinary dialogue remains citation-free. Malformed JSON gets at most one syntax retry with identical evidence and a token-counted stricter format instruction; no malformed prose is silently repaired into a successful answer. Stop/budget guards and final source validation apply to the retry. Invalid citations are not retried as syntax errors. Actual semantic and syntax failures remain in dialogue rather than being erased.

Interactive read-only operations now retain structured local activity on the same canonical dialogue turn; see HARNESS-ACTIVITY.md. It is excluded from model-history projection and cannot authorize replay, writes or network. A start commits before work, and success/failure/Stop is retained when completion can be persisted. An interrupted pending entry is shown as Incomplete; it is not inferred to have succeeded or failed. Older turns retain their historical status text rather than receiving fabricated receipts.
