# Model set contract

Model sets are named presets for the currently connected role selections stored in `Settings > Models`: text generation, decision routing, speech transcription, OCR, and image understanding. They are a convenience for selecting a known combination; they are not executable workflows, downloaded bundles, or device compatibility claims. The model role plan, including why media is a composed pipeline and the optional vision-language capability, is defined in [MODEL-ROLE-ARCHITECTURE.md](MODEL-ROLE-ARCHITECTURE.md).

The built-in text-only alternatives are `LFM3 · 1.7B · QAD Q4_0`, `LFM3 · 1.7B · Q8_0`, `Bonsai 2 · 2B`, `Bonsai 2 · 4B`, and `Bonsai 2 · 9B` (PC prose unstable). Media and pipeline sets use the app's default text model, LFM3 QAD Q4_0, and add only the selected specialist roles: `Text + speech` adds Whisper tiny; `Text + OCR` adds Tesseract 7; `Text + vision` adds LFM2.5-VL-450M; `Text + capture` adds Whisper tiny and Tesseract 7 without image understanding; `Text + image + audio` adds Whisper tiny, Tesseract 7 and LFM2.5-VL-450M; `Local pipeline` adds Open d1 Omni 600M, Whisper tiny, and Tesseract 7. A media preset therefore does not silently replace the chosen/default text model with Bonsai 4B. Each non-empty role must match both its app-owned model catalog and an app-owned adapter with that model ID and capability. Catalog presence and adapter declaration do not prove successful execution or device fit. These sets are task-oriented convenience presets, not a size ranking. Catalog-only entries such as D1 3B and Whisper base are excluded while their local runtime adapters are unavailable.

The 9B preset pins PrismML's Qwen3.5-derived PTQ1_0 text GGUF at revision `5b2abb02362efbed46bbe204014b02837778b2c2` (1,997,486,976 bytes, SHA-256 `3561df7ac7d26a71ffa991ac2db740b10841c3a350aa2676ccd3ff5d428b4e8b`). The already pinned WebML Community Space revision advertises 9B with PTQ1_0 and uses the same `Qwen3_5ForConditionalGeneration` runtime family. This establishes a connected candidate. PC browser generation reached output, but it contained corrupted punctuation and triggered the prose-quality guard; phone compatibility and usable quality remain unverified. Image input is not enabled for this model: the vision projector is not pinned or loaded. Applying the set only selects the role; it does not initiate its approximately 2 GB transfer, prepare or load it. Model and runtime licenses remain separate. The preparation review offers a read-only device check before download; it reports browser storage quota estimate and WebGPU adapter availability. Neither result measures peak GPU/RAM use or proves the model loads and generates. The check is advisory and never switches models or downloads assets.

Compatibility cross-check against PrismML's current official [Bonsai 2 9B GGUF card](https://huggingface.co/prism-ml/Ternary-Bonsai-2-9B-gguf) and [backend support matrix](https://github.com/PrismML-Eng/Bonsai-demo/blob/main/BACKEND-SUPPORT.md) (2026-10-29): the release is an 8.95B language model plus an optional 0.46B vision tower; PTQ1_0 is about 2.00 GB, PQ2_0 about 2.42 GB, Q2_0 about 2.56 GB, and vision requires a separate mmproj file. The official card specifies PrismML's llama.cpp fork for PTQ1_0/PQ2_0 and recent upstream llama.cpp for Q2_0. BabelShelf's pinned preset is PTQ1_0 paired with the separately fetched WebML Community WebGPU runtime; it is not running through that PrismML llama.cpp fork. Therefore, do not replace its packing with PQ2_0/Q2_0 or describe the preset as image-capable without a matching runtime, full model-format compatibility check, and end-to-end verification. These file sizes are not runtime-memory estimates or evidence of device fit. The currently recorded PC free-RAM preflight was 0.78 GiB, so no 9B load was attempted.

Choosing a set opens a review of each role assignment. Only explicit `Apply set` commits. The pending selection is locked against duplicate apply/dismiss while saving. A stale cross-tab revision refuses without overwriting; settings refresh and the user must choose and review again. A successful application updates the model preference record once, appends its revision using the existing preference writer, and adds selected built-in IDs to their role libraries. It preserves custom model declarations, previously registered library entries, downloaded/prepared assets, appearance, connection settings, memory files, schedules, and activity. It does not download, prepare, load, unload, or execute any model. Network/download settings remain unchanged.

The selector groups text-only choices, input-role sets, combined role sets, and user-saved sets. These are complete presets: applying one changes the reviewed role selections; it does not merely add a role. This presentation metadata is derived from built-in set IDs and is not added to the Memory schema. Quantization/model variants remain text choices, while speech, OCR, vision and decision stay distinct roles. Grouping does not alter preset composition, preparation, or application behavior.

Initial preparation uses these selections literally: text-only sets prepare only text, while a selected Vision role receives a separate pinned preparation step. This avoids silently downloading speech/OCR assets after a text-only choice. The review gives a transfer estimate, not peak RAM or a device-fit guarantee.

A selected set says nothing about whether the assets are present, the runtime can execute the model on a particular browser/device, or quality/performance is acceptable. Users prepare and verify assets separately. `Text + capture` means only Whisper transcription and Tesseract OCR. `Text + image + audio` additionally selects the separate Vision role but does not implement video-frame extraction or imply an Omni model. Future custom model registration remains an explicit separate flow; these presets never remove a custom registration.

Model assets can remain cached on local storage without remaining resident in working memory. The current inference owner keeps only one selected language model active at a time. Switching between Decision and Text can therefore require another load. To avoid repeated eviction on ordinary follow-up turns, the Send workflow now uses a resident Text model's own planner instead of loading Decision over it; it also reports the missing Text model before acquiring Decision when Text files are absent. On a cold start with both roles selected, Decision may still load once before Text takes over. This is a memory-pressure policy, not proof that both models can fit concurrently on a given device.

The list's `Cold assets` value is the full manifest size before subtracting any local files. `Text files found` is a local presence observation for the set's text model; it does not verify all roles in the set, rehash files, load the model, or establish device compatibility. The preparation review determines which selected assets are missing.
