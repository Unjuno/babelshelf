# Device diagnostics

The opt-in check is in **Settings → Developer → Device test**. **Run device test** checks the secure context, active service worker, app build, cache availability, temporary local-storage and isolated IndexedDB roundtrips, the production `KnowledgeStore` workflow in a newly created temporary database, a small OPFS write/read/delete probe when OPFS is available, WebGPU adapter availability, Web Locks availability for origin-wide model coordination, shared-WebAssembly threading prerequisites, and selected-model file readiness. The OPFS probe uses a fresh cryptographic filename, refuses a collision without writing, and removes only the exact temporary file it created; it does not open the model asset directory. Without Web Locks, separate app tabs may compete for device memory; the check reports this limitation but does not disable inference. The WASM fields report only whether cross-origin isolation, `SharedArrayBuffer`, and shared WebAssembly memory are available; they do not prove a selected engine activated a thread pool. The isolated Memory workflow creates, searches, revises, validates a backup of, and withdraws one synthetic note, then deletes only the database it created. It never opens the user's canonical database or reads user records, and never loads or runs a model. When available, diagnostics records a bounded list of WebGPU feature names, the fallback-adapter flag, and selected numeric buffer/workgroup limits. It omits adapter vendor and device name. These checks help diagnose runtime constraints; they do not prove a model format is compatible, a model fits in memory, or generation will work.

The report includes a **Home Screen launch** check. `standalone: false` means the check ran in a browser tab; it does not describe an installed Home Screen PWA run. Run the one-run cold-restart flow from the Home Screen app so its own storage and service-worker context are checked. The report's `manualSteps` are instructions only: their presence does not prove Airplane Mode or force-close happened. A completed return attempt is recorded separately under `offlineRestart`. Likewise, verified model files, a WebGPU adapter, recorded limits, or WASM prerequisites do not prove that model generation ran, used that adapter, or fit in memory. Only the explicit model test can provide a short generation result.

Model execution is a separate explicit action: **Run selected model test** loads the currently selected local model if needed, performs one short structured generation and discards its output. It passes only when the model returns exactly one JSON object with a single `answer` property whose value is `READY`; valid JSON containing any other answer is a failed smoke test. The UI warns that loading may use substantial memory and close the app. A model already loaded by the app is not unloaded by this test. For the offline restart handoff, model execution is unchecked by default; **Include selected model test after restart** must be enabled before starting. The continuation binds to the exact selected model ID and refuses to load if the selection changed or its local files are not ready. When the pinned runtime reports them, the copied report also includes a strict allowlist of numeric prefill/first-visible-token/decode timing, throughput, and memory counters. Arbitrary runtime strings, adapter identity, prompts, and generated answer text are discarded at the shared inference boundary. These values come from one short generation and are not a sustained benchmark.

Before using the iPhone, run `npm run test:ios-handoff` on the development PC. It builds the product PWA, serves that build locally, then checks the Settings path, local report creation, one-time continuation after reload, marker cleanup, and copy handoff in mobile-sized Chromium and Windows Playwright WebKit. Run it again only after changing this diagnostic flow; both are PC preflights, neither is iOS Safari, and they do not prove an iPhone pass.

The WebKit preflight is included in `npm run test:ios-handoff` and `npm run test:quality`; CI installs the pinned Playwright WebKit browser before running it. To run only the WebKit suite against a built app, use `npm run test:ios-handoff:webkit:built`. This catches browser-engine-specific regressions without consuming another physical-device run. It remains desktop WebKit evidence only; Safari/iOS clipboard, storage, standalone and OS behavior can differ. The app keeps a selected-text fallback for browsers that decline programmatic clipboard access.

For the repeatable PC regression set, run `npm run test:quality`. It runs the repository and prototype suites, static checks, a clean product build, product acceptance, custom-tool/runtime browser tests, the real-browser isolated Memory-store smoke, the iOS handoff UI regression, multi-process offline browser checks, and an installed-PWA cold-start check in order. The installed-PWA check uses a fresh Playwright Chromium profile, installs the PWA in standalone mode, stops the loopback app server, then starts the installed PWA in two separate offline browser processes and verifies storage/search/edit/import/restore workflows. It is PC Chromium evidence, not iOS Safari or OS-level airplane mode. GitHub Actions runs the same command on the development branch and pull requests.

## One-time iPhone handoff

After `npm run test:ios-handoff` passes on the development PC, use the iPhone sequence once:

1. In **Settings → Developer → Device test**, tap **Start one-run iPhone check**. BabelShelf stores a bounded baseline report and a continuation marker locally.
2. Turn on Airplane Mode, force-close BabelShelf, then reopen it from the Home Screen. The return checks run automatically and open Developer.
3. Tap **Copy test + context for Codex** and paste the copied handoff into the development conversation. It includes the bounded report and instructions to diagnose from that evidence, make fixes that can be verified on PC, and request another iPhone run only when a specific iOS-only fix needs verification.

The app marks the single return attempt before starting probes or the optional model smoke. If the page/process is interrupted during that attempt, the next launch finalizes the saved baseline as **interrupted** and does not automatically repeat any diagnostic or model generation. When a model test was requested, the report says its result is unknown/interrupted; it does not label it passed or failed. This prevents a crash-prone test from entering a relaunch loop; the handoff preserves the interruption as a warning rather than reporting a pass. A new physical run must be started explicitly.

An optional model generation is off by default. Enable **Include selected model test after restart** before starting only when that one-run test is desired; it runs only if the same model remains selected and its local files are ready. Its short output is discarded.

The browser cannot toggle Airplane Mode, force-close itself, reliably identify the iPhone model or iOS version, or prove those system actions occurred. The report records only browser-observed standalone mode, `navigator.onLine`, service-worker control, and the persisted marker, and explicitly flags those limits. A passing handoff does not establish all-function acceptance, sustained model quality, memory fit, thermal stability, or a general offline acceptance run. The automated PC reload test does not simulate iOS, Airplane Mode, or network isolation.

The probes write temporary uniquely named IndexedDB databases and delete only databases they created. The Memory workflow uses production storage code against its isolated database; it does not inspect the BabelShelf knowledge database, prompts, original attachments, user notes, or generated answer text. A failure report identifies only the fixed workflow stage (for example search or backup validation), never browser exception text or test content; IndexedDB failures use a fixed generic message, except for a recognized safe temporary-database collision notice. The saved report is local-only and contains build/runtime identifiers, platform/user-agent data, check outcomes, bounded WebGPU capability data, and (when run) bounded generation timings, token counts, and numeric memory counters. The selected-model section includes its registered engine, backend route (WebGPU or CPU/WASM), and model/runtime revisions when available. These are configured route metadata, not proof that the named hardware backend actually executed. Only the separate WebGPU adapter probe observes adapter availability, and neither it nor the route metadata proves that the selected model fits or ran on that adapter. Existing schema-1 reports without WebGPU details remain readable.

The continuation marker expires after 24 hours; an expired or malformed marker is removed without starting a test. Probes use browser cryptographic randomness. IndexedDB cleanup runs only when the diagnostic created that exact temporary database; a name collision is treated as a failure and leaves the existing database untouched. The test is fixed application code: it does not download or execute a test script, alter connection permissions, or send the report anywhere. Copying the report is an explicit user action. The copy formatter rebuilds the handoff from an allowlist of known report fields and nested diagnostic values; unknown properties (including prompt, note, answer, or raw-runtime fields) are omitted even if a local saved report is malformed or extended.
