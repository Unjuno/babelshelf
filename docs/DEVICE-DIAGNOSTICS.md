# Device diagnostics

Performance display: **Overall speed** is output tokens divided by the entire generation call, including input processing. **Decode speed** appears only when the runtime reports it; it is not inferred from the overall rate. The existing report fields and old reports remain unchanged. Neither number establishes sustained or thermal performance.

## Optional load phases (2026-10-27)

The WebML worker already measures verificationMs, importMs, runtimeLoadMs and totalLoadMs around actual asset verification, local runtime-module import and from_pretrained initialization (including its warmup). The Text hook now carries these values through the public inference port instead of discarding them. The port permits only finite nonnegative timings and an optional boolean runtimeModuleReused; adapter identities, prompt/output strings, arbitrary metadata and invalid counters are excluded. Device reports and copy handoffs share that projection. Older reports and runtimes without phase counters remain readable; unavailable counters are not filled with zero or inferred from the backend name.

The optional modelGeneration.loadMetrics object is diagnostic evidence, separate from the measured outer loadDurationMs (which includes app/Worker coordination). runtimeLoadMs is not pure GPU transfer or pure kernel compilation; it includes the runtime's complete model initialization. No knowledge edits, asset verification, model defaults, acquisition permissions, execution ownership or cancellation behavior change. Keeping verified local assets and a resident model remains distinct from caching a module import. No timing claim permits skipping hashes or silently downloading missing assets.

Open **Settings → More → Developer**. There is one **Run tests** action. **Test options** selects **Quick** (default) or **Performance**; it does not start a test by itself. Older control names below are superseded by this flow.

Prepare the desired text model in Models first. Tests use only locally prepared assets and never download missing models. In a browser tab, Run tests performs the checks and one selected-model generation immediately when its local files are ready. An installed Home Screen app instead saves the baseline and arms one post-restart attempt in that app's storage. Missing assets are reported as not-run, not as a generation pass.

**Quick** validates the exact structured READY response. **Performance** uses a fixed synthetic prose workload capped at 128 output tokens. It records model/runtime revisions, configured engine/backend, load time when loading was needed, input/output token counts, generation duration and supported runtime timing/memory counters. No knowledge, conversation or generated answer text enters the report. Missing counters remain unavailable; the configured backend is not proof of hardware execution. Load time for an already resident model is not a cold-load measurement.

For an installed PWA: choose the mode, tap **Run tests**, follow the displayed Airplane Mode/close/Home Screen reopen steps, then copy the report. The opt-in check is in **Settings → Developer → Device test**. **Run tests** checks the secure context, active service worker, app build, cache availability, temporary local-storage and isolated IndexedDB roundtrips, the production `KnowledgeStore` workflow in a newly created temporary database, a small OPFS write/read/delete probe when OPFS is available, WebGPU adapter availability, Web Locks availability for origin-wide model coordination, shared-WebAssembly threading prerequisites, and selected-model file readiness. The OPFS probe uses a fresh cryptographic filename, refuses a collision without writing, and removes only the exact temporary file it created; it does not open the model asset directory. Without Web Locks, separate app tabs may compete for device memory; the check reports this limitation but does not disable inference. The WASM fields report only whether cross-origin isolation, `SharedArrayBuffer`, and shared WebAssembly memory are available; they do not prove a selected engine activated a thread pool. The isolated Memory workflow creates, searches, revises, validates a backup of, and withdraws one synthetic note, then deletes only the database it created. It never opens the user's canonical database or reads user records, and never loads or runs a model. When available, diagnostics records a bounded list of WebGPU feature names, the fallback-adapter flag, and selected numeric buffer/workgroup limits. It omits adapter vendor and device name. These checks help diagnose runtime constraints; they do not prove a model format is compatible, a model fits in memory, or generation will work.

The report includes a **Home Screen launch** check. `standalone: false` means the check ran in a browser tab; it does not describe an installed Home Screen PWA run. Run the one-run cold-restart flow from the Home Screen app so its own storage and service-worker context are checked. The report's `manualSteps` are instructions only: their presence does not prove Airplane Mode or force-close happened. A completed return attempt is recorded separately under `offlineRestart`. Likewise, verified model files, a WebGPU adapter, recorded limits, or WASM prerequisites do not prove that model generation ran, used that adapter, or fit in memory. Only the explicit model test can provide a short generation result.

Model execution is part of the explicit Run tests action described above. Quick passes only for exactly one JSON object with a single answer property set to READY. A model already resident in the app is not unloaded by the test. A model loaded specifically for the test is unloaded afterward. The continuation binds to the selected model ID and refuses to load if the selection changed or local files are not ready. Bounded numeric runtime counters are allowlisted; arbitrary runtime strings, adapter identity, prompts and generated answer text are discarded.

## One-time iPhone handoff

After `npm run test:ios-handoff` passes on the development PC, use the iPhone sequence once:

1. In **Settings → Developer → Device test**, tap **Run tests**. BabelShelf stores a bounded baseline report and a continuation marker locally.
2. Turn on Airplane Mode, force-close BabelShelf, then reopen it from the Home Screen. The return checks run automatically and open Developer.
3. Tap **Copy report for Codex** and paste the copied handoff into the development conversation. It includes the bounded report and instructions to diagnose from that evidence, make fixes that can be verified on PC, and request another iPhone run only when a specific iOS-only fix needs verification.

The app marks the single return attempt before starting probes or the optional model smoke. If the page/process is interrupted during that attempt, the next launch finalizes the saved baseline as **interrupted** and does not automatically repeat any diagnostic or model generation. When a model test was requested, the report says its result is unknown/interrupted; it does not label it passed or failed. This prevents a crash-prone test from entering a relaunch loop; the handoff preserves the interruption as a warning rather than reporting a pass. A new physical run must be started explicitly.

Quick is the default mode; Performance is explicitly selected in Test options before Run tests. After restart, one model generation runs only if the same selected model has its local files ready. Output text is discarded.

The browser cannot toggle Airplane Mode, force-close itself, reliably identify the iPhone model or iOS version, or prove those system actions occurred. The report records only browser-observed standalone mode, `navigator.onLine`, service-worker control, and the persisted marker, and explicitly flags those limits. A passing handoff does not establish all-function acceptance, sustained model quality, memory fit, thermal stability, or a general offline acceptance run. The automated PC reload test does not simulate iOS, Airplane Mode, or network isolation.

The probes write temporary uniquely named IndexedDB databases and delete only databases they created. The Memory workflow uses production storage code against its isolated database; it does not inspect the BabelShelf knowledge database, prompts, original attachments, user notes, or generated answer text. A failure report identifies only the fixed workflow stage (for example search or backup validation), never browser exception text or test content; IndexedDB failures use a fixed generic message, except for a recognized safe temporary-database collision notice. The saved report is local-only and contains build/runtime identifiers, platform/user-agent data, check outcomes, bounded WebGPU capability data, and (when run) bounded generation timings, token counts, and numeric memory counters. The selected-model section includes its registered engine, backend route (WebGPU or CPU/WASM), and model/runtime revisions when available. These are configured route metadata, not proof that the named hardware backend actually executed. Only the separate WebGPU adapter probe observes adapter availability, and neither it nor the route metadata proves that the selected model fits or ran on that adapter. Existing schema-1 reports without WebGPU details remain readable.

The continuation marker expires after 24 hours; an expired or malformed marker is removed without starting a test. Probes use browser cryptographic randomness. IndexedDB cleanup runs only when the diagnostic created that exact temporary database; a name collision is treated as a failure and leaves the existing database untouched. The test is fixed application code: it does not download or execute a test script, alter connection permissions, or send the report anywhere. Copying the report is an explicit user action. The copy formatter rebuilds the handoff from an allowlist of known report fields and nested diagnostic values; unknown properties (including prompt, note, answer, or raw-runtime fields) are omitted even if a local saved report is malformed or extended.
