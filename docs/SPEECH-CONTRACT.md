# Local speech contract

Whisper tiny and Whisper base multilingual q8 use the same app-owned local Transformers.js/WASM adapter. A custom local import path accepts only a compatible eight-file Whisper ONNX package; other architectures remain unavailable. No text-model substitution, browser SpeechRecognition, remote inference or automatic processing-model download is used.

## Assets and execution

`speech-models.ts` owns the built-in package identities used by preparation, the worker and transcript provenance. `speech-manifest.json` pins onnx-community/whisper-tiny revision ff4177021cc41f7db950912b73ea4fdf7d01d8e7: eight assets totaling43,615,928bytes. `speech-base-manifest.json` pins onnx-community/whisper-base revision1846881b6b3a3024392c1eea3ad983695bc23925: eight assets totaling79,666,385bytes. Every file has a size and SHA-256. Each model reads only its own revision-specific cache and exact local URL prefix. Initial preparation checks the selected model, not a default tiny status. A prepared tiny cannot make base ready.

The current package locks Transformers.js4.3.0 and ONNX Runtime Web1.31.0-dev.20260914-8d85527a0. The speech worker, ONNX module and WASM are included in the size/hash-verified offline application shell. New transcript provenance records the current bundled Transformers version; historical tiny/custom transcripts tagged3.8.1 remain valid without rewriting their records. A base record cannot borrow tiny's revision or historical runtime tag. WASM single-thread execution is independent of Bonsai WebGPU. CPU/memory/latency on physical phones remains unmeasured.

Settings > Models > Add transcription model registers a built-in candidate or opens `Choose local Whisper model files`. The custom importer requires eight fixed metadata/tokenizer/quantized encoder/decoder files, inspects Whisper architecture and tokenizer structure, caps imports at 2 GiB and hashes every file before content-addressed OPFS storage. Custom model verification and inference are local-only. Registration status explicitly says execution is untested until a real inference succeeds. Unit263 follow-up confirms a real imported-weight transcription in PC Chrome with browser networking disabled and repeats it after page reload; a single 3.5-second synthetic fixture generated text, but its recognition accuracy was not established. Built-in Prepare requires Downloads & updates ON and verifies each pinned asset before putting it in the revision-specific cache. Normal operation re-verifies local model bytes and never repairs missing bytes with a download. Runtime custom-cache failures return terminal responses because Transformers catches thrown cache errors and would otherwise try local HTTP. Both model remote loading and generic remote URL use are disabled. The service worker only permits pinned preparation URLs; no user content is sent in downloads.

Whisper's base model is MIT. Its ONNX conversion card points to the same base. Transformers.js is Apache-2.0; ONNX Runtime is MIT with separate ThirdPartyNotices. Copies and source references are in design/prototype/licenses and the production shell. This does not resolve or alter the separate Bonsai WebML Community runtime redistribution-license gate.

## Startup status and processing gate (Unit47)

The read-only startup status call retains exclusive access to its speech worker, but reports no processing busy state. It does not transcribe, download, grant readiness before validation or block independent text-only Input. Concurrent calls on that worker still fail explicitly; prepare/transcribe continue to report busy throughout progress and completion. Stop/crash behavior is unchanged. A brief preparation request during status may return Speech model busy and is never auto-replayed.

## Input, review and persistence

Voice input offers Record and Choose audio. Recording uses getUserMedia/MediaRecorder for local bytes only; recognition uses the installed local model. A synchronous permission gate prevents duplicate requests; close/unmount invalidates pending requests and releases late-granted streams. Recording stops at120seconds. Imported originals are bounded to32MiB; supported browser codecs decode and downmix/resample to mono16kHz, then reject durations beyond120seconds. Decoder transient memory is not a phone-memory guarantee. Unknown/undecodable files refuse; video extraction is not connected.

Audio language is explicit and stored in canonical Settings/models.md. The default en is visible and old records gain it only during parsing; original revision bytes remain. The99 language codes are taken from the pinned generation config. Transformers3.8.1 does not automatically detect language: omitting the language defaults to English. Explicit ja materially changed the Japanese QA result but did not eliminate misrecognition. Language selection does not guarantee language accuracy.

The model processes the full bounded clip and returns text plus estimated segment timestamps. The adapter retains original model end estimates and clips playback ranges to the actual clip duration; Whisper can estimate an end beyond the clip due to padding. Nonfinite, unordered, out-of-range starts and invalid/inconsistent text fail validation. Timestamps remain model estimates, not forced alignment.

Review transcript includes the original player, exact generated text, language and estimated times. Cancel makes no knowledge writes. Use text appends recognized words to the existing composer draft and stages the original and verified transcript as a working input attachment. Other pending attachments and typed words remain. Nothing is submitted until Send. Fresh submitted originals keep their empty canonical raw projections; working recognition is stored with the dialogue, not automatically as a searchable knowledge transcript. Existing active originals can be reused without duplicate raw/projection records. Explicit Save note atomically creates an immutable raw original, its empty initial Markdown projection and a separate transcript note; an existing saved audio instead keeps its raw/projection and gains only the new transcript note. Duplicate approval, raw mismatch, path collision or withdrawn original aborts all writes. A synchronous save lock prevents duplicate clicks. A refresh failure after commit reports saved status and asks for reopening, not another Save.

Transcript metadata records schema/type, exact original ID/revision/SHA, model/revision/runtime/dtype, language, actual duration/processed coverage, original recognized text and estimated segments. Direct corrections append canonical note revisions; the first recognized text and raw audio remain. Memory and inline answer source previews open the exact original audio. An exact v1 transcript citation maps to overlapping recognized segments and opens the audio at the bounded estimated start, with a range label in the on-demand preview. Edited or unmatched transcripts open the whole recording and do not claim aligned timing. Native playback remains user-initiated. Withdrawing the original preserves transcript/history but excludes it and generated descendants from current evidence. State brainpacks preserve and validate the whole chain; legacy note-only imports cannot introduce orphan media transcripts.

Stop terminates the speech worker. Worker crashes discard that worker so retry can create a new one; stale callbacks cannot settle a later request. Closing the voice surface cancels pending decode/inference/permissions. A local developer-only ?check=speech route exposes real raw inference for diagnosis without downloads or knowledge writes; it is outside the normal interface.

## Remaining acceptance

Physical Android/iPhone microphone permissions, codec support, interrupted capture, installed PWA process cold start under OS network isolation, phone memory/thermal/latency and multilingual accuracy are pending. Custom Whisper import, selected-model provenance and one offline PC load/inference/reload flow are verified; broad accuracy and phone fit are not. Automatic ASR selection by the decision model, general image/video understanding and complete background scheduling are also absent. Working voice input retains the original recognition and its exact source/model/language metadata through dialogue backup. Recognized words have an exact user-prompt range only when that text occurs once unchanged; edited or duplicate text has no invented prompt placement. Runtime history includes only descriptor names/kinds/statuses; it does not serialize original hashes, model objects or the full voice provenance into model context. Current audio understanding still requires explicit local ASR review, not automatic decision-model routing. No complete-MVP claim follows from this unit.

## Video audio tracks

Explicit Transcribe audio on a video attachment uses the same prepared local Whisper and browser decoder, with the same120-second decoded-audio and32MiB original limits. A supported container must actually decode; missing audio or an unsupported codec reports failure. The reviewed original remains a video. No frame information is extracted or inferred. Review and sent descriptors explicitly identify audio-only processing.

Video transcripts require sourceTrack video-audio and timebase decoded-audio. Duration, coverage and segment times describe the decoded audio sample timeline, not a verified video/container timeline. Browser decodeAudioData does not establish their mapping, especially for delayed audio, offsets or edits. Source opening therefore shows Whole video / audio timing not mapped and never automatically seeks a video using those sample timestamps. Audio originals retain their existing estimated segment seek. Precise video frame/track mapping remains an implementation and verification gate.

A pending attachment keeps the same ID through transcription. Use text replaces that pending descriptor, keeping one original. Save note converts any matching pending descriptor to the stored reference before a later Send, preventing duplicate raw storage. Atomic save, withdrawal checks, immutable original bytes, first recognized text and history/backup validation are shared with audio. No automatic extraction, Decision dispatch, custom runtime or download was added.

## Recording lifecycle (Unit157)

Error, Cancel, voice-sheet dismissal and unmount detach handlers, clear the timer, stop the recorder and tracks, discard buffered/late data and never start transcription. ## Operation-scoped speech inference (2026-10-21)
SpeechClient terminates its inference worker on a final transcribe success or error before delivering the transcript/rejection to the caller. Prepared model files remain in storage; a later explicit request creates a fresh worker. Status/preparation may retain their non-inference worker. Late messages from a retired worker cannot change state or settle a new request. Stop still terminates immediately and does not replay. This bounds speech residency after inference; it does not establish peak-memory reclamation timing or prevent overlap with every other model before transcription begins.

## Reader entry ownership (2026-10-21)
Both Vision and Speech use inference-ownership.ts releaseIdleInference before inference dispatch. An active Text/Decision owner refuses reader startup; idle loaded owners unload sequentially with operation checks before/after each await. Speech reserves its request through this phase; Stop or a failed unload cannot dispatch a delayed transcription or replay. useSpeech keeps the current preflight callback separately from worker identity. Status/preparation do not unload inference owners. This is a same-component reader-entry rule, not a cross-tab lock or universal runtime scheduler.
