# Versioned built-in definitions

Tools Markdown describes the compiled local adapters. It is inspectable data, not executable code, a plugin installer or a permission grant. External/custom files remain inactive; the MCP example remains disabled. The local search/read, reviewed capture and ordinary-note correction adapters are connected. Generic settings, tool, task and log model edits are not enabled by this documentation update.

Fresh initialization seeds the current compiled definitions as v1. Existing initialization recognizes only the exact earlier app-owned v1 README, memory.capture and memory.patch bodies retained in `tool-definitions.ts`. It appends a canonical v2 through `reviseNote` inside the same notes transaction. The original revision, IDs and metadata remain intact. Repeated or concurrent initialization does not append another update.

Qualification requires the exact compiled ID, path, old body and current seed; an active original with protected/unmanaged UI metadata; one v1 revision; empty aliases and sources; and no imported/media origin. Modified, moved, withdrawn, imported, unprotected, managed or unknown records remain unchanged. This is a finite migration for three known documentation records, not a generic built-in overwrite policy.

Backup restoration is still exact and conflict checked. Restoring an old snapshot into an empty store preserves its original records. On subsequent normal initialization, a recognized old built-in can receive the retained documentation revision. Restoring old records over newer revisions reports conflicts and performs no writes. A backup containing an unrecognized definition is never treated as adapter installation or execution authority.

Unit12 verification includes pure eligibility/preservation tests, eight real IndexedDB checks, and a normal PC browser Check/Apply/reopen update. Native exports before/after confirmed all 37 note IDs and 11 run records retained; only the three known definitions and the explicitly toggled connection setting changed. Reopen/re-export matched the complete canonical notes/settings/runs snapshot exactly. See TEST-RESULTS.txt for build and evidence limits.
