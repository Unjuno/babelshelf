# Local calculation and interaction priorities

Keep the accepted UI. Reduce waiting, repeated input and navigation before adding configuration.
Explicit whole arithmetic inputs such as `(1200 + 800) / 4` or `calc: 2 * 3` use the bundled math.calculate code package before model load/compaction/planning. No attachments may be present. Ordinary prose, paths and ISO dates retain the ordinary request route. No document, filename or historical content is executed implicitly.

The tool uses a bounded recursive arithmetic parser, not eval/Function. Decimal/scientific numbers, parentheses, unary signs and + - * / (including × ÷ −) are supported. Results use finite IEEE-754 binary64 arithmetic; exact financial decimal, unit conversion, percentages and arbitrary code are unsupported. Division by zero, excessive size/depth and nonfinite results fail visibly through existing request handling.

The exact expression, result and trusted source identity are recorded through normal activity/CAS persistence. Answer remains in the conversation across reload. No knowledge note is automatically created, no citation is invented, no model or network is required. Existing reviewed Save remains separate. Package sources appear under protected Tools/math.calculate like search/read. Natural-language calculation routing and calculations over cited data remain future shared planner work; this direct route does not claim them.

Interaction priorities for subsequent harness work: reuse exact current attachments/file/result; retain draft on failure; expose brief progress and Stop only during actual work; require approval for mutations, not read-only calculation; show source/operation details on demand. Avoid new top-level screens or settings for ordinary tasks.
