# Local text decisions

The optional Decision role is separate from Bonsai text generation. Registration in Models is not preparation or runtime readiness. Only Open d1 Omni 600M currently has a bounded text adapter; the 3B catalog entry remains unavailable. Image/audio encoders are not installed by preparing the text graph. Decision outputs cannot read media by implication, generate answers or authorize edits.

## Local lifecycle

Prepare requires explicit Downloads ON and fetches only revision-pinned URLs without credentials. OPFS `babelshelf-decision-v1` stores verified files under their SHA-256. Streaming hash validation precedes load, and writes commit only after count/hash verification. Stop before replacement cannot turn into a cache miss/download. Readers are cancelled/released; failed downloads abort atomic writers. Status, load and classify never repair missing assets over the network. The worker restricts normal fetch to bundled runtime assets, served through the verified app cache.

Stop during preparation requests cleanup and gates competing commands until acknowledgement; a 2.5-second watchdog terminates a stuck worker. This graceful abort preserves any loaded session. Stop during load/inference terminates the worker; crashes, disposal and postMessage failures invalidate Loaded. Unload releases the session. Historical asset receipts do not establish current readiness. Preparation/load/unload use the on-demand processing ledger with manifest provenance.

## Typed protocol and limits

The original reserved tokenizer markers and calibrated choice/score/binary readouts are checked. Caller delimiters are escaped. Questions have finite bounded options and no arbitrary executable action. The product rejects excessive input/options rather than silently truncating their meaning; its initial input cap is 2,048 tokens within the model's 16,384-token architecture. Exact text graph inputs include prefix_len=0 and masked option positions. Inference tensors are disposed even on failure. Tokenizer/protocol fixture tests are not model accuracy evidence.

The isolated `?check=decision` diagnostic can exercise real prepared local inference without knowledge writes or downloads. It does not replace ordinary-input acceptance. Ordinary Send now uses selected, prepared D1 as an optional finite routing aid after existing dialogue compaction. A missing/unprepared role leaves the approved Bonsai planner available; ordinary work never acquires assets. A verified selected role may be loaded locally and its real classification is recorded in the turn activity, with model pins, exact current request, readable attachment descriptors, probabilities and selected route. D1 sees no historical requests, summary, receipts or citation bodies: actual native evidence showed old correction instructions competing with current intent. Full unchanged compacted dialogue stays with the contextual-query guard, structured Bonsai planner and answer generation.

Only validated choice outputs with confidence at least0.95 and margin at least0.25 may bypass the generative planner, and only for answer/summary/chat. These thresholds do not guarantee semantic accuracy. Captures, corrections, search/open parameters, exact earlier-message reads/transforms and schedules still need the structured Bonsai planner. Decision outputs cannot invent file IDs, paths, original-message indices, body edits or authorization.

Finite intent is not retrieval-query resolution. An answer/summary with any prior dialogue context and no current readable attachment scope always defers to Bonsai, even with a confident D1 intent. Otherwise a raw follow-up such as What about the second one? can search the wrong topic and drop its referent. Current attachments retain the existing fixed factual scope and dialogue context through readingEvidence; D1 supplies no attachment facts. All source validation, current-only references, unread-media guards and review-before-save/edit remain unchanged.

D1 input is never silently shortened to fit its2,048-token product cap. A typed context-limit work error is audited and defers to the existing planner. Stop, crash, invalid output and audit persistence errors propagate instead of pretending fallback succeeded. Captured model handles reject after their selection identity changes, including disable/re-enable while a Send awaits earlier text work. In-flight completions retain effect-epoch guards. Stop only discards D1 when its synchronous client has pending work; stopping another reader/generator does not discard an idle loaded D1 session. Physical Android/iPhone, all-process offline restart, language accuracy and resource limits remain separate acceptance gates.
