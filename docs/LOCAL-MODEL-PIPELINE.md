# Local standard model set and replaceable pipeline

Latest user decision (2026-10-18): provide a coherent standard model set and a working local pipeline first. Users may add custom models or replace the selected models. The harness dispatches capabilities, not a hardcoded single model. Keep current defaults until a replacement is explicitly selected; no implicit acquisition, network inference or executing model-supplied code.

Dependencies: trusted adapter registration -> verified local assets -> compatible role selection -> original extraction -> source-scoped retrieval/context budget -> generation/tool dispatch -> source/output validation -> reviewed mutations. Completion requires actual normal flows, not catalog entries.

## Product contract for the standard set

The standard set is a recommended compatible bundle, not a requirement to load every model at once. Initial preparation shows the required assets and downloads them only with explicit permission. Ordinary use selects the needed prepared processor for each step and releases workers when appropriate for device memory. Missing assets yield a preparation-required state, never a silent download or remote fallback.

The default user flow is: prepare the set once, submit text or attachments, and let the harness extract readable content, retain original provenance, retrieve relevant knowledge, and answer or propose an action. Deterministic tools such as calculation do not require model inference. A decision model is an optional routing aid; it is not the authority for writes or a substitute for media readers.

Replacing a model changes a role assignment, not stored knowledge, original attachments, citations, or history. Custom and recommended models use the same validated capability boundary. Accept a custom model only when an installed trusted adapter supports its actual architecture and processing contract. Otherwise show an unsupported state; adding an engine remains an application implementation task. A future omni adapter may serve several roles through this boundary.

Settings should present one consistent Add model and compatible-role selection flow. Users need not choose pipeline internals for each request. This contract describes the intended completed behavior; the implementation and acceptance gaps below remain explicit.

The standard set covers text generation, optional decision routing, speech transcription and image OCR. Existing connected choices are Bonsai/WebML, fixed optional ONNX text candidates, D1 text decision, Whisper tiny and Tesseract. These have different evidence/quality limits; their presence does not certify a complete useful standard set. PDF text uses bundled PDF.js rather than an LLM. Video currently contributes audio transcription only; frame/scene understanding is unsupported. Embedding, reranking and speech synthesis are optional future adapters, not installed capabilities. Future omni adapters may implement several capabilities without forcing separate models per role.

User customization uses Add model, compatible role assignment, explicit local import/preparation and verification. File extensions alone do not establish compatibility: architecture, quantization/operators, tokenizer/template or media pre/postprocessing, complete pinned assets and runtime licensing must match a trusted adapter. Existing validated custom GGUF text registration retains its own checks; the new fixed-adapter catalog does not replace it. General custom ONNX/omni installation is still incomplete.

Current implementation: local-capabilities.ts declares immutable app-owned fixed adapter capabilities with role-specific readiness decisions. Automatic image/audio/video-audio extraction now uses this shared decision before invoking the existing processor. Wrong-role or unconnected selected models cannot gain capabilities from a ready flag. PDF remains a built-in text reader. Settings video status shares this decision and distinguishes missing speech setup from prepared audio-only support. The catalog itself neither loads models nor grants acquisition/execution/write authority. Ready here is a live dispatch prerequisite, not accuracy, loaded state or phone acceptance; per-adapter checks and provenance validation still run.

Next integration: unify model-library compatibility metadata and preparation/status controls around these capabilities, retaining role-specific manifests and verifiers; connect additional text adapters with exact tokenizer/context accounting; route normal requests through available local capabilities and deterministic tools. Do not introduce catalog-only buttons or claim unconnected models runnable. Reserve comparative model experiments for final integration acceptance.

## Standard-set preparation integration
Initial preparation keeps the selected text model and fills only unconfigured speech/OCR roles with the existing supported readers. A selected, connected D1 text-decision model is now included in the same reviewed plan with pinned aggregate bytes and its existing verified asset operation. An unselected decision role stays unselected; an unconnected selected decision model refuses the plan before acquisition. Ready decisions skip preparation. Stop/failure prevents later steps and preference commit, retaining any verified assets already acquired for explicit retry. No model is automatically loaded or executed by preparation. The button waits for decision status checks like the other busy processors.

## Current combined PC evidence
Unit93 uses the already verified selected Bonsai4B, Whisper tiny and Tesseract eng+jpn set in the same current-build offline process, with bundled PDF.js and literal TXT/MD. One five-file Send actually extracts OCR/PDF/ASR, produces a sourced text answer and saves exact generated content after review. New offline process search/read/export/no-op restore and independent original-byte/history checks pass. No optional Decision or video-frame/scene processor is inferred from this set. It is preliminary PC integration, not a physical-phone/OS-disconnected acceptance certificate. The raw monolithic observer failure and separate successful continuation remain distinguished.
