## Current-result read metadata (Unit32)

Normal Send uses typed current/history dialogue targets and no dialogue.subject re-resolver. dialogue.read input records the resolved current turn identity (including derived legacy identity) or explicit historical index/speaker; it contains only portable JSON. An absent current result is null, never undefined. The result carries the exact retained original and its source links, from the same immutable prior snapshot. Retained dialogue.subject receipts remain readable historical evidence. See CONVERSATION-CONTRACT.md.

# Interactive harness activity

Activity is local audit data on each canonical dialogue turn (`ui-v1-dialogue`). It is not a second knowledge store, a tool registration or execution authority. Older turns without activity remain readable; no records are cleared or retrospectively fabricated.

The interactive adapter records allowlisted read-only stages: model load, bounded context/compaction, action selection, note search/read, original dialogue read, literal text operations, correction/new-schedule proposals and answer generation. `schedule.propose` retains the current instruction and typed task or clarification result, never a saved/executed claim. Existing approved correction writes retain their separate atomic correction receipts; scheduled runs retain their canonical execution ledger. PDF/speech extraction and explicit model asset operations use the separate processing ledger below.

`dialogue.subject` (Resolve speaker) records exact competing user/assistant originals and the finite model choice/final target before text inspection. It is used only for indexed recall/transform with a proposed USER original and latest ASSISTANT answer; capture and same-speaker chronology bypass. It cannot install, write, generate a replacement source or turn an audit record into context/authority. Unknown/none/malformed output refuses. The same bounded internal PlannerOutputError path as dialogue.plan retains actual raw invalid output and json/source/unresolved reason; other tools and arbitrary thrown properties cannot supply raw diagnostic data. See CONVERSATION-CONTRACT.md and Unit31 evidence; valid execution is not universal semantic accuracy.

`text.inspect` (Process original) records the exact selected dialogue target/current instruction and either a read decision or a validated deterministic literal result. It follows indexed recall and transform routes, while capture continues to reuse exact bytes. A read decision does not claim a completed answer or text change. A tool-returned failure retains its result and is marked Failed; it cannot trigger a prose replacement. Older `text.transform` receipts remain valid and unchanged. This extra model stage is read-only and does not authorize replay, storage or source substitution.

Each attempt stores schema1, a stable ID, operation name, exact bounded JSON input, start timestamp and status. The start commits with expected-dialogue CAS **before** the operation begins. Completion stores a detached result or a typed error and finish timestamp. Terminal entries cannot be completed twice or switched to another input/tool. Tool-returned failures retain both their result receipt and failure status. A failed start prevents execution; a failed final write never repeats the operation or asserts a tool failure after actual success.

A process interruption may leave `running` persisted. Outside that exact active input it is displayed as `Incomplete`: this does not claim the work failed, completed or never ran. There is no automatic replay. Stop retains a stopped attempt when the underlying operation returns/cancels; this does not promise instantaneous cancellation of GPU loading/compilation. Failure to persist a terminal record is shown explicitly and may leave an incomplete entry.

Activity payloads are portable JSON, limited to300,000 UTF-8 bytes each, nesting depth20,128 entries per turn. Invalid operation/status/time/result shapes, duplicate IDs, nonfinite values and cycles reject. Codes distinguish stopped, changed source, context limit, unprepared model, malformed model output, unavailable target and other failures. Messages remain local; error classification is a UI/audit category rather than proof of cause.

Normal conversation shows one small activity mark. The sheet opens short operation/state labels; details expose input/result/error on demand. Activity is explicitly excluded from dialogue history/compaction projection, search evidence and instruction parsing. Backups preserve and validate it as untrusted receipts. A rehashed backup does not convert an unknown operation into a valid one. User data and receipts are never uploaded by this flow.

A note read resolves from the same refreshed snapshot that hydrates its display. Navigation uses its resolved path. This prevents an activity saying a new version was read while an older in-memory list paints a different file/version. This is snapshot consistency, not a claim that another tab can never make a later edit.

Verification scope: pure lifecycle/control tests and real IndexedDB reopen/CAS/brainpack tests are separate from actual browser/model outcomes. Exact builds and observed failures are in TEST-RESULTS.txt. Incomplete activity, older status-only failures and unrelated historical source marks are preserved; this feature does not retroactively repair semantic answers or establish mobile/offline acceptance.


## Media processing history

Explicit PDF reading and audio/video-audio transcription persist schema1 `media-processing` receipts in existing `runs`, keyed `ui-v1-processing-ID`. Each wraps the same bounded Activity lifecycle with allowlisted `pdf.read` / `speech.transcribe`. The start commits before original preparation, decoding or extraction. A failed start prevents work. Terminal CAS accepts only the original running identity once, preserving input/tool/time; concurrent completion cannot overwrite a terminal. Cancellation checks surround asynchronous work and normalize an aborted decoder/worker rejection to Stopped. A terminal persistence failure never replays work or falsely asserts an engine failure. Interrupted running receipts display Incomplete outside the active attempt; no automatic replay.

Settings > Local files > Processing history opens receipts on demand. Rows show source label and Done/Failed/Stopped/Incomplete. Details reveal timestamp, bounded JSON input, result summary or error. Refresh and dismissal use the existing preview epoch: stale history reads cannot reopen or replace a newer sheet; an old cancelled PDF audit error may toast but cannot close another sheet. History queries use an IDB key-prefix cursor so original byte records are not copied into the list.

Inputs retain a fresh-file descriptor or stored original reference and display name, plus explicit speech language/selected model. File labels are untrusted display data, never evidence. Success retains original ID/hash, processor or actual speech-model revision/runtime, character count and `textStateHash` (the canonical stateHash of the exact returned string), page coverage or audio scope/duration/segment count. The result is a compact processing receipt; it does not duplicate the full extracted body or media bytes. `reviewRequired:true` means the returned extraction requires the existing review flow. Done proves processing completed, not that a note was saved, a transcript was accurate, or every media region was understood. Closing review retains the attempt but does not save extraction/original knowledge. Existing explicit Save/Use text/Send contracts remain unchanged.

Receipts from unsent files can therefore refer to an original that was never saved. They do not require an original-asset record and cannot be used as search evidence, context, a canonical transcript, write authority or permission to retry. Backup validates reserved prefix/type/ID/tool and lifecycle even after rehashing; exact records survive full-state restore. Older data is not retroactively fabricated or rewritten. There is no automatic pruning or replay; the existing 200MB/20,000-entry backup limits still apply. Very large history pagination/retention remains a separate usability requirement.

PC verification includes actual PDF.js extraction before/after audit writes, seven real-IDB lifecycle/restore checks, native multilingual PDF completion, password failure, actual Whisper video-audio recognition and Stop, reload, and exact backup/restore. Lifecycle-only concurrency/interruption fixtures are explicitly distinguished from inference. Physical microphone/device/background delivery/full offline-process acceptance and broader asset/device acceptance remain unverified or pending; see TEST-RESULTS.txt.

## Explicit model asset activity

Explicit Text Prepare/local Import/Load/Unload and Speech Prepare now use the same persistent processing history. The existing schema1 `media-processing` envelope and key are kept for old-record portability; its operation allowlist additionally contains `model.prepare`, `model.load`, `model.unload` and `speech.prepare`. Old receipts are not rewritten. Input snapshots retain role, model/runtime revision, file name/size/SHA-256, selected acquisition method and requested network flag. Local import records file descriptors only. No imported bytes, executable code or credentials are put in the audit payload. Success records the actual completed effect (verified-assets, loaded, unloaded); these are historical statements, never current readiness or inference compatibility.

The existing worker/cache/OPFS inspection remains the only readiness source. Restoring a successful preparation receipt never prepares a model, grants network, loads a runtime or triggers execution. Decision/custom candidates remain unconnected unless an actual verified adapter exists. Prepare is explicit and follows Downloads permission; load/unload/import remain local. No model/runtime pins or licensing decisions were changed by adding audit.

A synchronous AssetOperationGate reserves the operation before the first awaited audit write, avoiding duplicate clicks while worker busy is still false. Send, manual/automatic task claims, transcription and microphone permission/recording use live gates; task claims and pending/live recording prevent asset management in the reverse direction. A task poll rechecks before claiming after its asynchronous note read. Normal busy deferrals do not create failed scheduled executions. Stop is routed to the same active operation and classified separately; incomplete audit records are not replayed. A failed final audit write does not repeat preparation or change actual readiness.

Shared text-worker cached verification now propagates cancellation before opening a replacement writer; hash readers are cancelled/released in finally. An aborted cached-file check must never fall through to replacement/download/delete. The regression test executes the actual worker source with controlled file/OPFS boundaries; it is storage/cancellation evidence, not inference or physical-device evidence. Model/runtime manifests are unchanged; app worker hashes and baseline shell metadata update normally.


The selected prepared Open d1 text adapter now uses turn activities for local decision.load and decision.classify. The latter records exact current-only state, question/options, model/revision, context-scope flags, calibrated finite result and direct/defer reason; it does not carry original attachment bytes or duplicate historical instructions. A context-limit work failure may defer to Bonsai, but cancellation, malformed output, worker loss and ledger failures stop the request. Captured handles cannot reactivate a superseded selection while Send awaits other work. Synchronous pending-work Stop preserves an idle loaded decision session. These audit entries do not authorize a capture, correction, task or network connection.

Failed interactive `dialogue.plan` retains bounded raw invalid output and a validation reason (`json`, `object`, `action`, `query`, `historyIndex`, `historyPart`, `body`) as its on-demand activity output. `dialogue.subject` shares that finite internal error boundary for source decisions, as described above. Only the internal typed planner error on these two operations can supply it; generic thrown properties and other tools cannot. Raw text is capped at 8,192 UTF-16 code units with an explicit truncation flag. It remains untrusted local diagnostic data, excluded from model history, knowledge indexing and execution. Stop retains no partial output. A failed receipt write still fails closed without repeating inference or replacing it with a guessed action. Earlier failed receipts are not retroactively filled.
