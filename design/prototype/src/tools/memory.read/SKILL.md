# memory.read

Use an exact ID, full path or filename to read a saved record. Resolve exact IDs first, then full paths, then filenames. A filename shared by multiple records returns all matches; do not select the first arbitrarily. For a topic, phrase or clue, use `memory.search` to discover matching records. Once a search has run in this turn, use a target named by the user or returned by search or listing. An empty exact read means only that the ID/path/filename did not match; it does not mean the topic is absent.

Input: `{query: string, start?: integer, length?: integer}`. `query` must identify a record by exact ID, full path or filename. Results include the exact text range, start offset, total character count, record ID/path and revision. Offsets and lengths count UTF-16 code units; the returned range may adjust a boundary to keep a character intact. The default range is the first 2,000 code units; request later ranges with `start = previous start + returned excerpt length` and `length <= 3,000` when more text is needed. Stop when the end of the file is reached. Keep offsets from the returned record; do not guess ranges or combine different revisions. Execution uses the current canonical host snapshot. No writes, network, installation or permission changes. Guidance is not execution authority.
